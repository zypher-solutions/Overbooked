# The documents, in one list

> **Start with `PROJECT_REPORT.md`** (or the Word copy in `word/`). It explains everything. The others are for one job each.

| File | For | What it is |
|---|---|---|
| `PROJECT_REPORT.md` | Everyone | The complete picture: what exists, every screen and button, every fault, the business plan, what is left, decisions waiting |
| `PARTNER_ONBOARDING.md` | A new partner or developer | What to read, what access to give, setup on his computer, the rules, how two people work together |
| `SALES_SHEET.md` | The sales person | Features, plans and prices, call scripts, answers, what not to promise, commission |
| `HANDOVER.md` | The next working session | The latest state, open questions and the rules. Update it at the end of every session |
| `SETUP.md` | A developer | Install, run, reset, test |
| `ARCHITECTURE.md` | A developer | How the pieces fit and the main flows |
| `DATABASE.md` | A developer | Tables, database functions, the list of database changes |
| `APP_CONTRACT.md` | The mobile app developer | How to connect and call every function (out of date, see the report, item H1) |
| `RUNBOOKS.md` | Whoever runs the system | Backups, Zypher access, answering a shop's problem |
| `BRANCHING.md` | A developer | How GitHub branches and releases work |
| `PARTIAL_RETURNS_DESIGN.md` | The owner and a developer | A proposal for part returns. Not built |
| `word/` | Sharing | The Word copies of the report, the partner guide and the sales sheet |

**Removed on 30 October 2026** because the report replaces them (they are still in the git history): `ROADMAP.md`, `BUSINESS.md`, `LAUNCH_PLAN.md` and `TRENDZ_PARITY.md`.
